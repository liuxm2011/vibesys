- **影响范围**：同文件中的 `JWT_SECRET` 为占位符（`REPLACE_WITH_...`），无风险；泄漏的只有 MiniMax key。当前工作树和 `git ls-files` 已无此 key（grep 确认 0 命中），`.gitignore` 规则（`backend/.env`、`.env.*`）目前是齐的。

### P0-2 限流在 Workers 上形同虚设，登录暴力破解防护实际无效 — ✅ 已修复（commit `072524a`）

- **位置**：`backend/src/middleware/rate-limit.middleware.ts:6,17,42,59`
- **事实**（三个叠加缺陷）：
  1. 计数器是模块级内存 `Map`——Workers 每个 isolate / 每个 colo 各有一份且随时回收，实际限额 = 配置值 × isolate 数量；
  2. key 优先取 `x-forwarded-for`（`:42`），CF 默认保留/追加客户端传入的 XFF，攻击者每请求换一个假 IP 即可绕过登录限流（不可伪造的 `cf-connecting-ip` 却排在第二位）；
  3. 失效条目只在同 key 再次命中时覆盖（`:22-26`），Map 永不收缩，长寿命 isolate 持续吃内存。
- **放大因素**：学生初始密码 = 学号（`password.utils.ts:114`，格式固定如 `2311xxxxx`/`2313xxxxx`，见 `excel-import.utils.ts:60`），学号半公开。限流一旦被绕过即可批量撞库。
- **动作**：改用 **Cloudflare WAF Rate Limiting 规则**（改动最小，推荐）或 D1/DO 计数；限流 key 只用 `cf-connecting-ip`。

### P0-3 毕业设计白名单/开关只在查询接口校验，选题接口无服务端门槛 — ✅ 已修复（commit `8907e2a`）

- **位置**：`backend/src/routes/thesis.routes.ts:174-230`（`POST /select`）、`thesis.routes.ts:11-42`（`GET /status`）
- **事实**：`graduationEnabled` / `graduationWhitelist` 只在 `GET /status`（供前端 UI 判断）里校验；`POST /api/thesis/select` 只检查 `role === 'STUDENT'`。**未列入白名单的学生直接 curl 即可锁题**（排他性占用 131 题库之一）；`/api/graduation/generate` 同样无门槛。
- **影响**：属于服务端授权缺失——毕业设计模式开关形同前端功能开关。
- **动作**：在 `select` / `generate` 路由内加同一套白名单校验（约 10 行）。

### P0-4 Worker Secrets 配置状态无法从仓库确认 — ✅ 已处理（commits `a97190f` / `5edb5c0`）

> **复核发现**：实际情况比审查时更严重——`wrangler secret list` 确认线上只配置了 `JWT_SECRET`，`MINIMAX_API_KEY` 从未配置（AI 功能线上不可用）。后确认学校自部署 MiniMax 服务已下线，AI 生成改为依赖管理员配置的第三方 Provider，该 secret 无需配置；CI 断言相应只保留 `JWT_SECRET`。

- **位置**：`backend/wrangler.toml`（`[vars]` 只有 `FRONTEND_URL`/`NODE_ENV`）、`backend/src/app.factory.ts:75`
- **事实**：`JWT_SECRET` / `MINIMAX_API_KEY` 不在 wrangler.toml（做法正确），代码从 `c.env` 读取，即依赖 `wrangler secret put` 配置的 Worker Secrets。但 `cloudflare/wrangler-action@v3` **只 deploy 不创建 secret**，仓库层面无法确认这两个 secret 已在 Cloudflare 侧配置——若缺失，登录接口直接 500。
- **动作**：执行 `wrangler secret list` 核实；建议在 deploy workflow 末尾加一步 `wrangler secret list` 断言。

### P1-2 Prisma client 与 D1 adapter 大版本错配 — ✅ 已修复（commit `5016556`）

- **动作**：对齐大版本（client 升 7 或 adapter 降 6），或加 overrides 锁定。

### P1-3 前端无全局 401 处理 — ✅ 已修复（commit `7f90715`）

- **影响**：用户编辑文档途中 cookie 过期后，每次保存/生成都只弹错误提示，界面停留在无效会话。
- **动作**：request 层加 401 统一拦截 → 清 session → 跳登录。

### P1-4 VIEWER 前端门控漏网：ProjectDetail 三个侧栏面板 — ✅ 已修复（commit `09d6610`）
